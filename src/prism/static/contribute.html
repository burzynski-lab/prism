Contribute an analysis

Analyses are added by pull request. Model files and figures must be approved for public release by your collaboration.

Steps

  1. Fork the repository and copy analyses/_template/ to analyses/<analysis-id>/. The id (lowercase, hyphens) becomes the URL of the analysis page.
  2. Fill in analysis.yaml. The signal_region text is shown with every result, so describe the selection precisely.
  3. Add the model files and predictor.py.
  4. Write README.md, the model card: what the analysis selects, the training samples, the validation and known limits.
  5. Put validation figures (PNG) in figures/ and list them in the record. Optional validation rows become a table.
  6. Open a pull request. CI checks the record and imports predictor.py and its requirements. Once merged, the analysis goes live with the next deployment.

Directory layout

analyses/
  my-analysis-id/
    analysis.yaml        # the record (schema below)
    predictor.py         # inference code
    README.md            # model card
    surrogate.pt         # model file(s) named in the record
    figures/
      sr_efficiency_m5.png
      closure_probability.png

Record schema

analysis.yaml

id: my-analysis-id            # directory name, lowercase, hyphens
title: Search for ...
short: one-line description
experiment: ATLAS | CMS | LHCb | other
status: draft | example | preserved
version: "1.0"
updated: 2026-08-29
contact: name <email>
references:
  - {label: "arXiv:2505.02429", url: "https://arxiv.org/abs/2505.02429"}
signal_region: text describing the selection the efficiency refers to
inputs:
  - HepMC2 or HepMC3 ASCII, generator level, ...
predictor:
  type: my_bdt                   # the class registered in predictor.py
  model: surrogate.pt
requirements: [xgboost]          # Python modules predictor.py imports
default_max_events: 20000
max_events: 50000
validation:                      # optional table rows shown on the analysis page
  - {sample: "...", actual: 0.43, predicted: 0.38}
figures:                         # optional, files in figures/
  - {file: sr_efficiency_m5.png, caption: "..."}

default_max_events pre-fills the submit form and max_events caps a single job; pick values that finish in minutes. Bump version and updated when the model or record changes, since both are shown with every result.

predictor.py

The file defines one Predictor subclass registered with @register("<type>"), and predictor.type in the record names it. Helper modules can sit next to it and be imported relatively. 

from prism.predictors import Predictor, finish_summary, register

@register("my_bdt")
class MyBDT(Predictor):
    def __init__(self, analysis, device="cpu"):
        super().__init__(analysis, device)
        import xgboost
        self.booster = xgboost.Booster(); self.booster.load_model(str(analysis.model_path))
        self.config = analysis.record["predictor"].get("config", {})

    def run(self, hepmc, max_events, progress=None):
        from prism.hepmc import read_hepmc
        probs = []
        for batch in read_hepmc(hepmc, max_events=max_events):
            x = event_features(batch.part, self.config)      # any function of the event record
            probs.append(self.booster.inplace_predict(x))
        per_event = np.clip(np.concatenate(probs), 0, 1)
        yield_ = [{"name": "expected signal-region yield", "value": float(per_event.mean() * sigma_pb * 1e3 * lumi_fb),
                   "unit": "events", "note": "for 1 pb and 140 fb^-1"}]
        return finish_summary(self.analysis, {}, per_event, quantities=yield_), per_event, {}

read_hepmc yields batches holding every particle of every event: identity, status, mother and daughter links, kinematics and production vertices. finish_summary adds the efficiency, its uncertainty, the histogram and provenance; objects and quantities add anything else to show, such as a yield. Add new packages to pixi.toml and list them under requirements.

Two optional record keys: assets ({name, url, extract}) downloads large model files once, for example from Zenodo, into analysis.assets_dir. options ({name, label, choices, default, help}) adds a selector to the submit page, passed to run(..., options=...). The CalRatio entry uses both.
